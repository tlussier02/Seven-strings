Implemented checkpoint-aware restarts in the current local project. No commit or push was made.

1. **Architecture found.** `PlayerFallDetector` and `SettingsMenuController` used `GameplayReset`, which synchronously reloaded the active scene. The developer reload button bypassed it. All three now request the same checkpoint-aware restart. Legacy `ResetGameplay()` and `RestartCurrentGameplayScene()` entry points remain compatible. Both restart modes retain scene reloads, so transient objects, UI, coroutines, input, harmony, and audio sources are reconstructed rather than partially reset.

2. **Chart files inspected.** `Assets/Beatmaps/beatmap-test.json` contains the current JSON schema used by `3dLanes`. `MovementPrototype` actually referenced `Assets/Beatmaps/Level Mapping - Test 3.csv`, despite `ChartLoader` now exclusively parsing JSON. Its 31 existing jumps were migrated into `Assets/Beatmaps/movement-checkpoints.json`, which the scene now references. The CSV and the prototype JSON remain unchanged. The migration uses `(CSV beat - 1) * 500` milliseconds at 120 BPM; JSON beats are zero-based. The original jump times and order are preserved, from 2 to 31.5 seconds.

3. **Existing schema.** `BeatMap` has `bgm`, string `bpm`, string `offset`, and `charts`. Each chart contains notes (`uuid`, `songPos` in milliseconds, `beat`, one-based `lane`) and links (`uuid`, `startNote`, `endNote`). `ChartLoader` already interprets same-beat linked endpoints two lanes apart as `NoteData.IsCheckpoint`. It converts `songPos / 1000` to seconds and sorts events by time. No timing format or parser schema was added.

4. **Checkpoint representation.** The new chart adds notes `mid_track` and `mid_track_end` in lanes 1 and 3, connected by `mid_track_link`. They share `songPos: 10000` and `beat: 20`. The checkpoint ID is the start-note UUID, matching the existing parser. The marker is excluded from note judgement and track gap/beat-prompt generation.

5. **Exact timing.** The checkpoint is at **10.0 seconds, zero-based beat 20**, or beat 21 in the source CSV. Its time is read from the chart on activation and again on restore; C# does not contain this timestamp.

6. **Files created.** `Assets/Scripts/Gameplay/CheckpointManager.cs` and its `.meta`; `Assets/Beatmaps/movement-checkpoints.json` and its `.meta`; `Tools/Validation/CheckpointValidation.cs`; this report.

7. **Files modified.** `Assets/Scenes/MovementPrototype.unity`; `Assets/Scripts/Audio/ScheduledAudioPlayer.cs`; `Assets/Scripts/Audio/StemLayerMixer.cs`; `Assets/Scripts/Gameplay/GameplayReset.cs`; `Assets/Scripts/Gameplay/NoteManager.cs`; `Assets/Scripts/Gameplay/PlayerController.cs`; `Assets/Scripts/Gameplay/PlayerFallDetector.cs`; `Assets/Scripts/Gameplay/ReceptorClock.cs`; `Assets/Scripts/Tools/DevTools.cs`; `Assets/Scripts/Tools/LevelTools.cs`; `Assets/Scripts/UI/SettingsMenuController.cs`. Previously untracked duplicate CSV/audio assets were left untouched.

8. **Activation.** The scene-local manager subscribes to `ReceptorClock.OnBeat`. Once the DSP-backed gameplay timeline reaches its authored marker, it activates once. A player already below track height cannot activate it. Marker activation is independent of hit/miss judgement. `HasCheckpoint` prevents repeated activation, including after a restore.

9. **Player position.** `CheckpointSpawn_mid_track` is an authored scene Transform at `(0, 1, 150)`, identity rotation, center lane index 1. At player speed 15, this is the 10-second position. Existing track tiles meet beneath it at ground height zero; the capsule bottom is at zero. Designers can move the Transform and author its rotation/lane through the manager Inspector.

10. **Central restart decision and lifetime.** `GameplayReset.RequestRestart()` checks for an active checkpoint in the active scene. Without one it reloads normally. With one it carries only the scene path and checkpoint ID through that requested reload. A one-shot `sceneLoaded` callback consumes and clears this token, resolves the new scene's authored marker, and restores gameplay before `Start`/first gameplay update. No Player, audio source, or gameplay manager is made persistent. An ordinary scene load, menu return, or reopened level has no token and starts fresh. Static state is also cleared at runtime initialization, including when domain reload is disabled. `ClearCheckpoint()` clears the scene-local activation for an explicitly started new run. If an authored marker disappears, restoration falls back to the normal fresh scene.

11. **Audio seek.** `ScheduledAudioPlayer.ScheduleFrom()` stops each newly created stem source and sets `timeSamples` from the checkpoint seconds and that clip's sample rate. The existing tick then calls `PlayScheduled()` for all stems using the same new scheduled start.

12. **DSP synchronization.** A new `ScheduledStartTime = AudioSettings.dspTime + 2` gives the normal lead-in. `AudioSettings.dspTime` is never assigned. Every restart establishes a fresh reference, preventing accumulated restart drift. Stem mixer beat/bar alignment also subtracts the checkpoint offset when finding the logical song-zero reference.

13. **Gameplay clock.** `ReceptorClock` derives song time directly from `SongOffset + dspTime - ScheduledStartTime - LatencyCompensation`. It no longer accumulates frame deltas after synchronization. `FoundOvertime` still gates gameplay until the new scheduled start plus calibration compensation. Existing countdown and pause behavior use the same DSP reference.

14. **Note/event indices.** `NoteManager.Seek()` clears active notes and finds the first note whose timestamp is at or after the checkpoint. `ReceptorClock.Seek()` similarly positions its event index. Earlier notes and holds are skipped; future notes remain available. The receptor processes all due events in a loop so a delayed frame does not leave the chart behind. Empty/exhausted charts use an infinite next-event time safely.

15. **QTE/ad-lib status.** The local parser recognizes long linked spans as QTE but explicitly excludes those from its returned events. `QteRegion` is a data-only struct; there is no active QTE/ad-lib controller or UI in the inspected scripts. This implementation preserves that behavior and does not claim to enable future QTEs. Scene reload clears any scene-local transient state; the shared event seek skips earlier events. If a QTE controller is added later, its separate event cursor must use the same checkpoint seek contract. No QTE redesign was made.

16. **Movement reset.** Scene reload recreates the original capsule/collider, Rigidbody, movement fields, and input. Player lane/jump tweens are explicitly killed on destruction. Restore applies the authored position/rotation to Player root and Rigidbody, zeros linear/angular velocity, restores lane origin and ground height, and synchronizes physics transforms. Roll currently has an empty implementation, so no roll state exists to clear. The scene's pre-existing missing input/lane-prefab references required input lookup and serialized lane-width/jump-duration defaults; these prevent null-reference failures without adding movement mechanics.

17. **Harmony.** Scene reconstruction calls the existing `HarmonyMeter.Awake()`/`ResetMeter()`. Both restart modes reset to normal starting harmony (currently zero). No historical harmony is reconstructed; stem fade state is recreated too.

18. **Before checkpoint.** Falls, Settings Restart, legacy bindings, and the developer reload button reload the current scene at its original player position and zero song offset. Audio/chart, notes, input, harmony, and transient state restart from the beginning. `3dLanes` and `3dTurn` have no authored checkpoint manager and continue to follow this path; their scene files were not modified.

19. **After checkpoint.** The same triggers reload the current scene and restore the checkpoint spawn, song offset, and chart/event indices together. The checkpoint stays active for subsequent restarts of this run. The Settings menu closes before restart; restart also explicitly clears global time/audio pause.
